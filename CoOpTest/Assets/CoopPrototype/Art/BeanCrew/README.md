# Bean Crew characters and props

The player is now one of four goofy "Bean Crew" workers sharing a single skeleton and animation set:

| # | Name | Look |
|---|------|------|
| 0 | Bolt | the eager rookie: mustard hoodie, red pompom beanie, big nose |
| 1 | Gus | the foreman: round belly, hard hat, hi-vis vest, huge moustache |
| 2 | Pip | the nervous engineer: bowl cut, round glasses, lab coat, buck teeth |
| 3 | Dot | the fearless mover: backwards cap, ginger ponytail, overalls, freckles |

## How it works in game

- `CharacterAppearance` (on `Prefabs/NetworkPlayer.prefab`) holds the four `Crew_*` renderers. The server picks an outfit nobody is wearing when a player spawns and stores it in a NetworkVariable, so every peer (including late joiners) sees the same outfit.
- Press **C** (while the cursor is captured) to cycle your own outfit. The key is editable in the Inspector.
- `PlayerAnimation` drives `Art/BeanCrew/Animations/BeanCrew.controller`:
  - `Speed` (0–1): Idle ↔ Walk, Carry ↔ Carry Walk
  - `Carrying` (bool): from the replicated held item
  - `MoveRate`: scales walk-cycle playback with speed (`walkPlaybackRate` on the component)
  - `Pick Up` plays when a player's held item goes from nothing to something
  - `Throw` follows `PlayerThrow`'s server clock (release pose ≈ 0.27 s, matching `releaseDelay` 0.25 s)
  - `Wave` is included but not wired to input yet
- Root motion is off; the server CharacterController still owns movement.

## First-person view

The game starts in **first person** (V toggles third person).

- Your own body is hidden from your camera (it still casts a shadow). Instead you see outfit-matched arms: `NetworkPlayer > Owner Camera > First Person Arms` (`FirstPersonArms` component), built from `Models/FirstPersonArms.fbx` (one left/right pair per outfit, source `Tools/Art/BeanCrew/fp_arms.py`).
- Arms are procedural: the hands pump while you run (speed from `PlayerAnimation.NormalizedSpeed`), sway when you look around, grip the sides of whatever you carry, heave it up on the throw wind-up and shove forward on release (timed from `PlayerThrow`'s server clock). Pose and motion values are all Inspector fields.
- While you carry an item, its **visual child** is shown in your hands, on your screen only. The networked item and its collider still follow the server hold point, which is what other players see (your full character carrying it).
- Arms and the held item render on layer 8 **FirstPersonView** through the `View Model Camera` (URP overlay in the owner camera's stack), so they don't clip into walls. The main camera excludes that layer.
- Other players never see your arms; they see your third-person character and its animations.

## Editing

- Blender sources: `Tools/Art/BeanCrew/BeanCrew.blend` (rig, 4 meshes, 7 actions) and `BeanProps.blend`.
- They are generated by `bean_crew.py` / `props.py` (Blender 5 or the `bpy` Python module): `python3 bean_crew.py <outdir>`. Re-running overwrites the FBX/blend output, so keep hand edits in Blender and export from there if you change them manually.
- Export settings: FBX, -Z forward, Y up, no leaf bones. Props use *Apply Transform* (baked axis conversion) so their root has no rotation.
- Materials: `Art/BeanCrew/Materials` (URP Lit, generated once from `BeanPalette.json`; edit freely, re-running setup keeps them).
- Adding an outfit: model it on the same `BeanRig`, export, then add its renderer to `CharacterAppearance.variants` and its name to `variantNames`.

## Props

`Art/BeanCrew/Models/Props`: BeanCrate, PowerCell, Wrench (pickup visuals), Generator, Workbench, SlotTray, BatteryDock, WorkshopDoor, BigButton, PendantLamp (+ PendantLampGlow switched by the generator state), and decor: TrafficCone, OilDrum, PalletStack, Pegboard.

Every visual is a child named `Bean Visual` under the original networked/physics object. Colliders, NetworkObjects, sockets and UnityEvents were left untouched; the old block renderers are only disabled. Decor lives under `Workshop Decor` in the scene with static box colliders and no networking.

## Setup tool

`Coop Prototype > Art > Apply Bean Crew (characters + props)` (`Editor/BeanCrewSetup.cs`) configures importers, builds the controller, dresses the prefabs and the scene. It is safe to re-run: existing materials, the controller and existing `Bean Visual` children are reused.

## The previous worker

- `Art/Legacy/WorkshopWorker_Legacy.prefab`: the old worker with its materials and `WorkshopWorker.controller`.

- On `NetworkPlayer.prefab`, the old visual is kept as the inactive child `Legacy Worker Visual`. To switch back, activate it, deactivate `Bean Visual`, and point `PlayerAnimation.animator` at its Animator.
